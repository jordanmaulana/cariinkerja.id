Crawl & Assess — how it works

How a paid preference turns into scored jobs: where its crawl URLs come from, what each job board returns, how job titles are matched, and what to check when a preference only gets LinkedIn results.

Written 1 Nov 2026 against main @ a9e701d plus the uncommitted title-matching fix (title_has_words). Re-render: weasyprint _docs/crawl-and-assess.html _docs/crawl-and-assess.pdf

1What it is

One Celery task, crawl_and_assess_preference (assessment/tasks.py), does the work for one preference: it crawls every URL in Preference.crawl_urls and queues an AI assessment for each job it finds. Three things start it:

Two admin buttons, two behaviours

Regenerate URLs

Replaces crawl_urls with the fresh standard list. URLs you added by hand are lost. It does not crawl.

Crawl & Assess Now

Merges: keeps the saved URLs in their order, appends any standard URL that is missing, saves, then queues the crawl. Hand-added URLs survive. The flash message says “added N new crawl URL(s)”. Enabled when the preference has a title or URLs.

Merging never removes anything. If a URL builder changes (say, a new parameter), the old variant stays next to the new one until you click Regenerate. That is harmless: jobs are de-duplicated by url, so it only costs one extra request.

5Title matching rule (Workable)

Workable's search is fuzzy (“developer” also returns “Business Development”), so for Workable we keep a job only if its title contains every word of the preference title. The code is in jobs/scrapers/filters.py.

1

Split the preference title

title_words("Logistic Operational") → ["logistic", "operational"]. Lowercase, split on anything that isn't a letter or digit, drop one-letter fragments (“C Developer” → ["developer"]).

2

Trim each word to its stem

  • -al after -ion or -ic is dropped: operational → operation, logistical → logistic, technical → technic.
  • A trailing -s is dropped on words longer than 4 letters, but not -ss: logistics → logistic, analysts → analyst. “ios” and “aws” stay as they are.
3

Every stem must appear in the job title

A plain substring check on the lowercase job title, so “operation” is found inside “Operations”.

# jobs/scrapers/filters.py
def _stem(word):
    if word.endswith("al") and word[:-2].endswith(("ion", "ic")):
        return word[:-2]
    if len(word) > 4 and word.endswith("s") and not word.endswith("ss"):
        return word[:-1]
    return word

def title_has_words(title, words):
    t = title.lower()
    return all(_stem(w) in t for w in words)

Limits

  • No synonyms: “Mobile Developer” misses “Flutter Engineer”, “Operational” misses “Ops”.
  • Substring match: “sales” → “sale” also matches “Wholesale”.
  • Before 1 Nov 2026 the rule had no stemming, so “Operational” matched no “Operations” title.
  • Skill Map pages use their own word-start rule (title_matches) and were not changed.

6After the crawl: relevance check, then score

assess_job runs once per job and preference (retried up to 3 times on errors):

  1. Already assessed? Skipped. (The admin button re-scores those through reassess_assessment instead.)
  2. Relevance gate check_relevance, a cheap AI call. It rejects a field mismatch, or a job not open to applicants based in Indonesia (residency-restricted, or needs a foreign work permit). The residency flag is ignored for explicit on-site/hybrid jobs, since the candidate may relocate. A rejected job gets an Assessment with is_relevant=False, score 0, verdict “Filtered as irrelevant: …”.
  3. Score assess(): skill match and gap lists, a 0–100 score, and a short verdict in casual Bahasa (“kamu”). A job type or remote-option mismatch caps the score (about 30 for one, about 15 for both).
  4. Push: a new Assessment is sent to the user's open browser tab (Redis → SSE).

Users only see relevant assessments (is_relevant=True) in the app. The admin preference page lists every assessment, filtered ones included. So “the user only sees LinkedIn jobs” can also mean the other boards did return jobs and the gate filtered them. Look for verdicts that start with “Filtered as irrelevant”.

7Troubleshooting: “only LinkedIn results”

Case study: “Logistic Operational”, full-time, hybrid

Live test on 1 Nov 2026, each URL from section 2 crawled with limit=10, nothing saved:

BoardBefore fixAfter fixWhy
LinkedIn1010Loose search finds related titles across SEA (Singapore, Malaysia, Indonesia…).
Himalayas00No job title contains “Operational”. Even “Logistics Operations” only returns jobs locked to US/UK/PH/DE/PK, which the gate would reject.
Jobicy00No logistics jobs at all in the APAC feed for the last 7 days.
Workable02The API returned Indonesian logistics jobs; the old exact-word rule dropped them because their titles say “Operations”. Fixed by stemming (section 5).
Remote OK00The ~100-job feed had no logistics operations role.

Takeaway. The remote boards carry mostly tech jobs and match words strictly. For on-site or hybrid non-tech roles, LinkedIn and Workable bring most of the results. Zero from a board is often normal, not a bug.

Checklist

1

Are all boards in crawl_urls?

Open the preference page. If a board is missing, click Crawl & Assess Now (merges it in) or Regenerate URLs (replaces the list).

2

Did the gate filter them?

In “Latest assessments”, check the Source column and look for verdicts that start with “Filtered as irrelevant”.

3

Did a board fail?

Search the worker logs for crawl failed for preference= or listing fetch failed. The crawl_health_check Discord report shows each board's health and the reason for a zero.

4

Is the worker running the new code?

After deploying scraper changes, restart the Celery worker. It keeps running the code it loaded at startup.

5

Probe each URL directly

Sends real requests (LinkedIn waits about 2.5 s per job) but saves nothing:

uv run manage.py shell
>>> from profiles.models import Preference
>>> from jobs.scrapers import scraper_for_url
>>> pref = Preference.objects.get(id="<preference id>")
>>> for url in pref.crawl_urls:
...     mod, src = scraper_for_url(url)
...     print(src, len(list(mod.crawl(url, limit=10))))
6

Is the title worded like real job ads?

Unusual wording finds little on the strict boards. Suggest the title that ads actually use, e.g. “Logistics Operations” or “Logistics Staff” instead of “Logistic Operational”.
